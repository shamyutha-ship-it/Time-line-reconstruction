1 How to Launch the Web Application

The system can be launched in three flexible ways depending on whether you want an offline desktop application or a browser-based forensic workspace.

Method A (Recommended)

1-Click Batch Launcher

Double-click run_app.bat inside the project folder. This spins up the local server on port 8000 and automatically opens your default browser at http://localhost:8000.

Method B

Native App Window (Python)

Run python launch.py in terminal. It searches for Edge/Chrome and opens a dedicated, frameless window mode (--app), providing an authentic desktop app experience.

Method C

Direct Browser Open

Double-click index.html directly in Chrome, Edge, or Firefox. The analyzer is fully client-side and requires no external internet or cloud backends.

4 Step-by-Step Investigation Workflow

Step 01

Configure Case Details

Click on "Incident Case #01" and "Lead Examiner" at the top to personalize your case number and investigator title. All changes are saved automatically.

Step 02

Ingest Evidence

Drag files directly into the dashed drop zone or click "Browse Files". The engine automatically reads the internal metadata, extracts JPEG EXIF camera dates, and skips duplicates.

Step 03

Automatic Reconstruction

The analyzer immediately sorts every file in exact chronological order (Oldest First). Review the sequence badges (#1, #2, #3...) to observe how the timeline of events actually unfolded.

Step 04

Annotate & Note Findings

Type notes inside the "Add an investigator note..." input field for key files. Explain forensic relevance, suspect identification, or compromised directory locations.

Step 05

Search & Filter

Use the search bar at any time to instantly isolate specific files (e.g., typing .mp4 or draft or specific dates).

Step 06

Export Official PDF Report

Click "View / Export Report" at the top right, verify the Case Dossier and Event Ledger, then click "Download PDF / Print". Select "Save as PDF" in your printer dialog.

5 Forensic Integrity & Security Principles

  • Zero Cloud Transmission: All hashing and metadata extraction occurs locally within the browser sandbox using the W3C Web Cryptography API. No file is ever transmitted over the internet.
  • Cryptographic Non-Repudiation: SHA-256 hashes ensure that files presented in the final report cannot be altered or repudiated without invalidating the checksum.
  • EXIF Camera Extraction: When JPEG media from mobile phones or digital cameras is ingested, the engine reads internal Exif headers to prioritize original capture time over filesystem modification time.
  • Duplicate Elimination: Ingesting identical files multiple times does not contaminate the timeline; the analyzer detects identical filenames, sizes, and timestamps and alerts the user.
